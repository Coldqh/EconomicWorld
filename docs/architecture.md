# Economic World — архитектура Phase 1

## 1. Что моделируем

Phase 1 — замкнутая минимальная экономика из 100 домохозяйств, 10 компаний, двух коммерческих банков, правительства, центрального банка и пяти товарных рынков. Мир живёт без игрока: люди ищут работу, получают зарплату, платят налоги и потребляют; фирмы нанимают, производят, закупают промежуточные товары, меняют цены, берут и погашают кредит, входят на рынок и уходят с него.

Важное событие не создаётся сценарием. Банкротство следует из нехватки ликвидности и пропущенных платежей, новая фирма — из незакрытого рыночного предложения и доступного капитала, цена — из издержек, запаса и реализованного спроса.

## 2. Архитектура

Применён модульный монолит с чистым детерминированным ядром. Для первой вертикали он проще распределённой системы, воспроизводим в тестах и не закрывает путь к worker-потокам или серверной симуляции.

```text
UI (React, только представление и команды)
  ↓
Simulation Facade / Scheduler
  ├── Labour Market
  ├── Production & Goods Market
  ├── Banking & Credit
  ├── Government & Taxation
  └── Metrics & Diagnostics
        ↓
Global Ledger + Domain Event Log + Goods Movement Log
        ↓
IndexedDB save repository
```

Подсистемы не меняют денежные остатки напрямую: они вызывают операции ledger. События описывают уже произошедшие факты и содержат ссылки на причины.

## 3. Источники истины

| Данные | Источник истины | Производные представления |
|---|---|---|
| Деньги, доходы, расходы, долги | неизменяемые транзакции Global Ledger | остатки счетов, капитал, денежная масса |
| Товарные остатки и потребление | Goods Movement Log + текущий индекс запасов | дефицит, выпуск, продажи |
| Занятость | связь `household.employerId` и список работников фирмы | безработица, вакансии |
| Кредит | договор `Loan` и проводки выдачи/погашения | кредитный портфель и просрочка |
| Цены | решения фирм после клиринга рынка | CPI и инфляция |
| История причин | Domain Event Log с `causeIds` | новости и causal trace |
| Время | Simulation Clock (`elapsedMonths`) | месяц, квартал, год |

Кэши остатков существуют только как ускоряемый индекс ledger и полностью восстанавливаются из проводок.

## 4. Минимальные доменные сущности

- `Household`: навыки, предпочтения, работодатель, банк, потребление и ожидания.
- `Company`: собственник, товар, работники, мощности, технологии, запасы, цена и состояние ликвидности.
- `Bank`: резервы, депозитные обязательства, кредитные активы, капитал и кредитная политика.
- `Government`: налоговые ставки, счёт бюджета и трансферты.
- `CentralBank`: ставка, резервные счета банков и денежная база.
- `Good`: единица измерения, вес потребления и технологическая рецептура.
- `Loan`: кредитор, должник, ставка, остаток, срок и просрочка.
- `LedgerAccount`, `LedgerTransaction`, `DomainEvent`, `GoodsMovement`.

## 5. Граф зависимостей

```text
Simulation Clock
  → обслуживание кредитов
  → рынок труда
  → зарплаты и налоги
  → социальные трансферты
  → закупки факторов производства
  → производство
  → клиринг товарных рынков
  → адаптация цен и зарплат
  → банкротства / вход новых фирм
  → правило ставки ЦБ
  → метрики → инварианты → UI
```

Рынки зависят от ledger только через публичные операции. UI зависит от снимка мира и не является источником экономического состояния.

## 6. План вертикальных срезов

1. Скелет мира, часы, типы агентов и начальные балансы.
2. Переводы депозитов и двойная запись.
3. Рынок труда → зарплата → подоходный налог.
4. Производство, промежуточные закупки и пять товарных рынков.
5. Банковский кредит, проценты, погашение и списание.
6. Банкротство и вход новой фирмы как следствие состояния.
7. Метрики, causal log, диагностика и прогон 20 лет.
8. Адаптивный UI и сегментированные локальные сохранения.

## 7. Экономические инварианты

- сумма дебетов каждой транзакции равна сумме кредитов;
- для каждой книги `активы + расходы = обязательства + капитал + доходы`;
- активы владельцев в депозитах равны депозитным обязательствам банков;
- резервы банков равны резервным обязательствам центрального банка;
- кредитный актив банка равен обязательству заёмщика и остатку договора;
- денежные депозиты создаются только при инициализации или выдаче кредита, уничтожаются только погашением principal;
- товарный и денежный остаток не бывает отрицательным;
- работник одновременно числится не более чем в одной фирме;
- все сотрудники фирмы ссылаются на неё как на работодателя;
- счёт клирингового рынка после расчётов равен нулю;
- одинаковое состояние даёт одинаковый следующий шаг.

## 8. Рискованные места

- **Двойной учёт требований.** Депозит одновременно является активом клиента и обязательством банка; операции создают согласованные проводки в обеих книгах.
- **Производительность 20-летнего прогона.** Финансовая история растёт быстро; UI читает агрегаты, а сохранение сегментирует ledger и события.
- **Погрешности.** Деньги хранятся целыми копейками, ставки — basis points; округление распределяется при клиринге.
- **Искусственные пороги.** Порог банкротства лишь юридически завершает процесс, а причины — реальные пропуски платежей и нехватка ликвидности.
- **Агрегация.** Phase 1 моделирует домохозяйства индивидуально, но товарный рынок клирится пакетно. Платёж каждого домохозяйства и расчёт с каждой фирмой остаются трассируемыми.
- **Сохранения в браузере.** GitHub Pages не даёт backend; используется IndexedDB, а формат версионирован для будущей миграции на серверное хранилище.

## 9. Формат сохранений

IndexedDB содержит отдельные object stores:

```text
manifests       saveId → версия, дата, название, симуляционная дата
snapshots       saveId → mutable state без длинных журналов
ledgerSegments  saveId:segment → до 1 000 транзакций
eventSegments   saveId:segment → до 1 000 событий / движений товаров
```

Формат имеет `schemaVersion`. При загрузке сегменты собираются в точном порядке; snapshot не подменяет финансовую историю.

Длительный прогон выполняется в отдельном Simulation Worker. UI передаёт snapshot один раз, получает только прогресс и итоговое состояние, может отменить расчёт и коммитит мир одним обновлением. Закрытие книг использует индекс счетов по владельцу и один проход по денежным потокам месяца вместо повторного сканирования всего ledger.

## 10. Структура проекта

```text
src/core          ledger, event log, clock
src/domain        типы мира
src/economy       создание мира, месячный цикл, метрики, инварианты
src/persistence   IndexedDB repository
src/ui            React-интерфейс
tests             автономный 20-летний прогон и инварианты
docs              архитектурные решения
.github/workflows GitHub Pages deployment
```

## 11. Технологический стек

- TypeScript strict для единого ядра в браузере и будущих workers.
- React 19 + Vite для адаптивного статического приложения.
- IndexedDB для локальных, не ограниченных объёмом localStorage сохранений.
- Node test runner для быстрых тестов без отдельного фреймворка.
- GitHub Actions + GitHub Pages для публикации статической сборки.

## 12. Первая playable milestone

Пользователь открывает «Пульт мира», видит реальные агрегаты и может запустить один месяц, год или автономные 20 лет. Он наблюдает занятость, цены, выпуск, депозиты, кредиты, фирмы и банки; открывает проводки и причинные события; сохраняет и загружает мир. Успех milestone определяется не красивой цифрой, а зелёными экономическими инвариантами после 240 месяцев.
